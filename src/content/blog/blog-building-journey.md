说起来可能少了点情怀，不像很多人那样是出于纯粹的技术热爱 —— 想要搭建这个站点的念头，最初萌生在我大二准备找实习的时候。

## 现实的开端：简历上的“作品集”

大二找前端实习的时候，我发现好多 HR 都要求提供作品集，Boss 上有些岗位还专门把作品集算作加分项；大家也很看重团队协作，会翻你的 Gitee / GitHub 看仓库操作。

可问题是，我早期做的东西基本没往远程仓库推过，最多就是逛逛 GitHub、把喜欢的东西下下来。真到投简历的时候，我总不好拿着视频或者一堆散文件去给人看——大家时间都宝贵，很难有人愿意一份份点开。

尤其是在牛客上，好不容易发简历过去有人理了，对方往我邮箱发链接让我填材料，里面就有作品集这一项。我那会儿对项目管理意识很薄弱，连 README.md 都懒得写，材料填得匆匆忙忙，果不其然后续就没音信了。于是我开始在网上找资料，“个人博客”这个念头就这样冒了出来。

## 实习时的触动：原来博客是“发光的电子手账”

后来暑假在外实习，和一位实验室朋友在同一家公司。聊着聊着，她跟我说实验室其他人都有自己的博客，上面发的东西能看出他们学到了好多。

我去看了看，确实很厉害——我觉得一件事能从想法真正落地，本身就很了不起。而我当时的博客，还停留在“没弄出来”的阶段。

再后来，我一直反复看很多优秀的人的博客，一边看一边感慨，也被激发出好多兴趣：原来个人网站不只是装作品的，还能存笔记——整理巩固自己的知识，也给他人留一份经验；偶尔的感想、生活爱好，甚至评论点赞互动，都能被装进去。

我越来越喜欢看博客，觉得它就像“一本会自己发光发亮的电子手账”，也越来越想做出一个属于自己的。

**后来慢慢明白，一个人做过什么，如果没人看见、自己也没记下，那它就像从未发生过。博客不是给别人看的橱窗，而是替未来的自己，把走过的路一盏一盏点亮。**

## 折腾到底：一眼相中 Astro 与 navfolio

先想清楚要一个什么样的博客：静态还是动态？纯手搓还是找个喜欢的框架？需要哪些技术栈？服务器配置够不够、要不要再买？域名怎么买……一系列问题慢慢考虑。

找主题框架的时候，我一眼就相中了 [navfolio](https://github.com/dodolalorc/astro-navfolio)——基础功能跟我的需求相似，尤其是主题风格我真的很喜欢，Vibe、blog 的页面布局直接狠狠相中。

本站基于 [Astro](https://astro.build) 构建，从 [navfolio](https://github.com/dodolalorc/astro-navfolio) 开源模板起步，代码已全部 vendor 到本地，由我独立维护和修改，随我的想法持续演进。内容全是纯文本，版本由 Git 管理；搜索用的是 Pagefind 静态索引；部署交给 Cloudflare。

好不容易把东西稍微部署起来，又要调成自己的样子：改功能、加功能、打磨内容……确实花了不少精力。中间踩坑无数，但也正是在这个过程中学到了很多：比如用 Axios 统一实例封装请求、按业务模块拆分接口文件；引入 Vant 2 组件库，并学会查找和使用阿里云图标库；熟悉 npm/yarn/pnpm 包管理器；上手状态管理乃至本地持久化；用 PostCSS 做移动端 vw 适配；用 ESLint 做代码检查等等。

但就这么一步步搭出来了。终于。
