梳理小程序 onLoad、onShow、onHide、onUnload 的触发规则，结合页面栈与跳转方式、分析 tabBar 页面和普通页面生命周期行为差异，避开重复请求、页面状态残留等问题。

## 页面栈：压栈、出栈
页面栈是微信小程序、uni-app（遵循小程序规范）核心的路由管理机制，理解它，才能更好地理清页面跳转、返回行为和生命周期的联动关系。

栈是后进先出的数据结构：
- **压栈（push）**：打开新页面，将新页面放到栈的顶部
- **出栈（pop）**：点击左上角返回，移除栈顶页面，回到上一页

> 网页 vs 小程序页面栈区别
> 1. 普通网页：依靠浏览器历史记录管理前进后退，跳转时旧页面默认销毁，没有常驻页面栈机制
> 2. 小程序 / uni-app：为了贴近 App 的使用体验，采用页面栈管理，页面可以驻留内存，区分 tabBar 页面与普通页面，生命周期划分更精细

## 核心生命周期：onLoad、onShow
### onLoad(options)
页面初始化生命周期，**页面实例创建时触发，整个页面生命周期仅执行一次**。
- 作用：接收路由参数 `options`、页面初始化、首次接口请求
- 触发条件：页面实例全新创建
- 注意：页面实例创建完成后，只要没有被销毁，`onLoad` 不会再次执行

### onShow
页面变为可见状态时触发，**可以多次重复执行**。
触发场景：
1. 页面初次创建，`onLoad` 执行完成后，会紧跟着执行一次 `onShow`
2. 从子页面返回上一级页面
3. 点击底部 tab 互相切换
4. 小程序从后台切回前台

只要页面状态从「隐藏」切换为「可见」，就会触发 `onShow`。

## 配套反向生命周期
- **onHide**：页面被隐藏、切到后台时触发
- **onUnload**：页面实例彻底销毁、释放内存，仅执行一次；销毁后页面内所有变量、状态全部清空

## tabBar 页面 和 普通非 tab 页面生命周期差异
### tabBar 页面（首页、我的、统计这类底部tab页面）
核心特点：
- 小程序启动后，tab 页面提前初始化并常驻页面栈底部，**常驻内存，永远不会触发 onUnload**
- `onLoad`：每个 tab 页面只执行一次
- 反复切换底部 tab：只会交替触发 `onShow ↔ onHide`，不会再次执行 `onLoad`

时序示例：
1. 第一次打开首页 tab：`onLoad`（仅一次）→ `onShow`
2. 切换到「我的」tab：首页 `onHide`，我的 `onShow`
3. 切回首页：首页 `onShow`，不再执行 `onLoad`

### 普通页面（navigateTo 打开的二级页面）
页面不会永久常驻，页面出栈后会被销毁，再次打开时重新创建实例。

#### 场景1：navigateTo 跳转 + 返回出栈
1. 首页（tab页面）通过 `navigateTo` 打开服务历史页：新建页面实例 → `onLoad` → `onShow`

   页面栈：`[首页, 服务历史]`
2. 点击返回：服务历史执行 `onUnload` 销毁、出栈；首页触发 `onShow`

   页面栈：`[首页]`

#### 场景2：普通页面打开后，直接点击底部tab切换（switchTab）
小程序规则：调用 `switchTab` 切换底部 tab 时，**页面栈里所有非tab普通页面全部执行 onUnload 销毁，tab页面常驻内存，不会被销毁**

时序：
1. 当前栈：`[首页, 服务历史]`
2. 点击底部「我的」tab
3. 服务历史页面销毁（`onUnload`）
4. 首页触发 `onHide`，「我的」tab页面触发 `onShow`，页面栈仅保留所有tab页面

## 四种跳转API汇总表
| 跳转 API | 使用场景 | 页面栈变化 | 后续执行 switchTab 的影响 |
| ----------------- | ------ | --- | --- |
| `navigateTo`| 打开详情、二级子页面（最常用） | 新页面压入栈顶，上一页保留 | 栈内所有普通页面全部销毁，tab页面保留 |
| `redirectTo` | 替换当前页面 | 销毁当前页面，新页面替换位置 | 栈内剩余普通页面依旧销毁，tab页面保留 |
| `switchTab` | 切换底部tab导航 | 清空全部非tab普通页面，只保留tab页面 | 仅在tab页面之间触发 onShow / onHide，tab页面不会销毁 |
| `reLaunch` | 关闭所有页面，打开指定页面 | 页面栈全部清空重建 | 全部页面销毁重建 |
